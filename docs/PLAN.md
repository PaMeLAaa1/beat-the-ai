# 暴打 AI：首版实施计划

## 产品判断

目标用户是对 AI 取代工作感到烦躁、想短暂发泄的人。首页先用「听说，你想替代我？」和 AI 的「你的工作，我已经学会了」建立冲突，再把全部操作压缩为点它、按住打。

成功标准：首次进入无需理解规则即可出拳；一次按下就有视觉反馈；10 秒内能看懂 AI 从嘴硬到求助；打爆后无需跳转或重新加载。

## V1 范围

| 项目 | 实现 |
| --- | --- |
| 平台 | GitHub 开源的静态网页，兼容手机和桌面 |
| 角色 | 原创 AI-001，全自动超级员工；终端屏幕、AI 标识、对话 |
| 输入 | 主指针/左键点击、按住；聚焦后 Space |
| 核心循环 | 100% → 每击下降 → 嘴硬/慌张/乱码 → 人工接管 → 自动重启 |
| 打击反馈 | 形变、拳头、粒子、连击、合成音效 |
| 设置 | 静音、减弱动态，本地保存 |
| 工程 | 原生模块、无依赖、Node 内置测试、MIT |

不做职业问卷、多个关卡、真实 AI 对话、成长系统、社交分享卡、排行榜、登录、付费或小程序封装。先确认点击手感和主题表达，再评估扩展。

## 数值与状态

默认初始进度 100，每击伤害 4；按住 250ms 后进入每 100ms 一击；最快有效单击间隔 70ms；900ms 无命中后连击归零。每轮约 25 击。

进度 >60 为嘴硬，25～60 为慌张，1～24 为乱码；0 进入 broken 900ms，然后 rebooting 600ms。重启后回到 100，并要求重新按下，避免自动挂机重复循环。

暂停冻结游戏逻辑时间。低帧率时最多每帧补一次按住命中，不追赶所有丢失的 tick。

## 工作顺序

1. A 建仓、落接口与入口，初始化 main，使云环境可拉取。
2. B 实现视觉与音效；C 实现状态、输入、测试；两者并行。
3. A 接入模块，检查可访问性、事件、页面生命周期与资产引用。
4. 运行逻辑测试、语法检查和 HTTP 冒烟测试；具备浏览器后实测手机与桌面。
5. 源码与文档提交 GitHub；部署静态试玩，只有拿到成功结果后交付试玩链接。

## 后续判断

先收集三件事：用户是否理解「AI 想取代我」、首击是否够爽、是否愿意再打一轮。只在这些得到验证后考虑职业台词包、更多 AI 表情或 PWA；App、小程序和插件不属于首版。

## 风险与处理

- AI 焦虑：以幽默台词和游戏结果承接情绪，不承诺治疗焦虑，不把就业预测伪装成游戏事实。
- 版权：原创 SVG、系统字体、程序生成音效；避免真实 AI 品牌与角色。
- 设备表现：限制粒子和音频声部数量，减少移动端抖动，提供减弱动态。
- 隐私与成本：纯前端，无采集和 API 费用。
